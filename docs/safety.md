# 予算、承認、永続状態

## OpenAI月額3,000円の停止ゲート

対象はこのエンジンから呼ぶChat Completions。月境界はJST。金額はDecimalで計算し、円の小数第2位まで切り上げる。上限はコードで3,000円固定。

ライブを許可する将来の運用では、専用OpenAIプロジェクトを使い、他のジョブや手動APIから課金を発生させない。公式のモデル単価、請求状況、保守的な為替上限（必要に応じ税金・手数料を含めた係数）を運営者が確認して予算JSONをローカルに用意する。アカウント全体の課金をこのリポジトリから制御することはできない。元の運用計画のAPI目安500円は維持し、3,000円は安全停止の上限である。

`config/budget.example.json` は全て未確認値で、ライブ実行できない。実設定には次を指定する。

|キー|条件|
|---|---|
|month_jst|現在のJST年月 YYYY-MM|
|observed_at|月内既存支出を確認した時刻。タイムゾーン必須、未来不可、24時間以内|
|rates_valid_until|公式単価の確認有効期限。タイムゾーン必須、期限切れ不可|
|exclusive_project|他の課金元がない専用プロジェクトであることを確認してtrue|
|month_spend_jpy_upper_bound|当月既存支出の円換算上限。取得も推定もできなければnullのまま停止|
|usd_jpy_upper_bound|保守的なドル円換算上限。確認できなければnullのまま停止|
|models|モデル名ごとのinput_usd_per_millionとoutput_usd_per_million。両方正の値必須|

単価や為替の自動取得は行わない。確認済み入力がなければ推測のデフォルト値で補わない。Usage/Costs APIのアクセス権限や課金を今回追加していない。

入力のUTF-8バイト数＋4,096トークンの余裕、最大出力2,500トークンから一回の費用上限を推定し、既存支出上限＋当月の全予約費用＋今回予約が3,000円以下の場合のみAPI呼出しを許可。予約はAPI前に永続保存。実使用量が返っても予約額は解放しない（過小計上を防ぐ）。最新支出が台帳予約と重複していても控除せず保守的に計上する。

応答にusageがない、型不正、推定トークン上限を超過、通信失敗ならunknownを保持。その月の次のAPI呼出しは停止する。公式請求記録との照合なしでunknownを解除しない。これは確認済み単価と換算上限を前提とする保守的推定であり、入力に誤った価格を設定した場合の実請求額を保証するものではない。

## 承認と投稿

JSON全体をキー順固定・空白なし・UTF-8で正規化してSHA-256計算。生成台帳の本文と一致する記事のみapprove可能。postは承認ハッシュ、一致する保存本文、最新の商品台帳による品質検査を再確認する。記事ファイルを編集してから同じ承認で送ることは不可。approveは編集者が明示的に実行するコマンドで、Actionsには含めない。状態ブランチの改変権限は信頼できる編集者とCIに限定する。

## Actions間の永続化と障害対応

`editorial-state` 専用ブランチのledger.jsonを毎回復元。キャッシュやartifactに依存しない。初回のみブランチが存在しないことをGitが正常確認できた場合に作成する。ブランチを削除すると初回扱いになるため、削除・force-pushを禁止して保護する。履歴の削除や手動リセットは禁止。プロジェクトや記事の秘密情報を台帳へ入れない（履歴はリポジトリ閲覧者から見える）。

状態はファイルロック中に更新し、原子的に置換、Git commit/push成功を確認してから外部送信する。pushはforceなしで、古い同時実行はnon-fast-forwardで停止。Actionsのconcurrencyでも一列に実行する。`--state-git-dir`指定時は保存対象が `.state/ledger.json` と一致しない指定を拒否する。

生成前にキーワード＋モードの試行意図を保存。完了したキーは次回スキップ。失敗・中断したキーは停止し、勝手に再生成しない。本文類似検査も永続記事履歴から行う。

投稿前にモード＋記事ハッシュのpendingを保存。成功時はWordPressのidとdraft状態を確認しcompletedにする。pendingでもcompletedでも同じモードでの再投稿を拒否（URL表記や接続先が変わっても再送しない）。通信タイムアウトや成功直後のクラッシュで結果不明になった場合はWordPress上の下書きを人が照合する。自動リトライではなく停止することで重複投稿を防ぐ（WordPress標準RESTには汎用の冪等POSTキーがない）。

復旧はブランチ履歴と公式請求・WordPress結果を照合し、必要ならレビュー付きの台帳訂正を行う。自動解除コマンドは提供しない。複数マシンで利用する場合も同じGit台帳を復元し、ライブにはGit checkpoint必須。ローカルモックは `init-state` で独立した試験用台帳を作れるが、本番履歴の代わりに新しい台帳を使ってはいけない。
